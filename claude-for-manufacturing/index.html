01 / SYSTEM VIEW

这套系统真正解决什么？

不是重新制造一个 MES 或 ERP，而是把已有系统里的证据连起来，让智能体完成“准备工作”，把决定权交还给业务人员。

先区分三层： GitHub 仓库公开的是 Skills / Contracts / 连接器配置与辅助脚本；模型工具调用与 Agent 运行环境由 Claude 提供；ERP、CAD、MES、CMMS 仍是实际数据源和业务系统。官方将该仓库标注为 Reference implementation，非积极维护。

File-first

支持把定期 CSV 导出作为正式输入方式，而非必须采购新的实时 API。12 个基础技能中有 11 个无需实时连接器也能开展相应工作。

Contract-first

用明确的数据契约定义每个 Skill 的输入和输出，避免多个任务重复理解同一份原始工厂数据。

Human-in-the-loop

把生成草案、业务审批和系统实际写入分开；生产日报是唯一设计为无人值守运行的组合链。

06 / MANUFACTURING CASES

工业场景：能力与边界并列看

以下为官方插件描述的目标工作流，并非独立验证过的真实工厂部署案例。

USE CASE 01

机床故障诊断

用停机前传感器窗口、维修备注、照片和 OEM 手册排序候选原因；人工选择成本最低的区分性测试。

breakdown-diagnosis · downtime-record
USE CASE 02

每日生产运营

从 ERP/MES/质量导出计算 OEE、停机损失与工单异常，并定时更新看板；不等于数学优化的全局排产。

data-consolidate · morning-plant-pulse
USE CASE 03

质量异常 / 8D

把检验值与规范条款关联，再验证各系统时钟，开展 SPC 与根因候选分析，生成可追溯 8D 草稿。

ncr-writeup · root-cause-capa
USE CASE 04

图纸与加工报价

解析询价、复用成本与工艺路线、估算工时并生成报价草案；不包含五轴 NC 自动编程与机床后处理验证。

rfq-to-quote · quote-build
USE CASE 05

CAD 参数探索

在已有 Fusion 参数化模型上生成变体，再读取计算结果做方案比较；不进行无依据的自动结构设计。

design-space-explore · trade-study-report
USE CASE 06

供应商切换

从供应商可能导致的质量问题出发，形成备选询价、价格与交期比较，由采购负责人确认决策。

supplier-escape-to-alternate-source
07 / IMPLEMENTATION NOTES

如何借鉴到自己的工业 Agent？

先复用流程与数据契约，再决定替换运行时或连接器；不要把参考 Skill 当成经过实机认证的控制软件。

值得直接研究的模块

  • data-consolidate：跨系统主键映射、导出数据新鲜度与缺口报告。
  • shared/contracts：把 Skill 之间的交接转成结构化、可测试的记录。
  • approval-gates：限定人工同意的具体范围，防止“同意一个步骤”被扩展为批量写入。
  • root-cause-capa：以统计计算支撑故障原因候选，而不是语言模型臆断。

仍需要自行补齐的工程能力

  • 工业系统真实认证、权限、审计、读写接口与数据质量治理。
  • 跨天任务持久化、失败重试、幂等执行与调度平台。
  • 多租户隔离、Agent Runtime、沙箱、服务可观测性与评测。
  • 若涉及 CNC/PLC 控制，需要独立的安全互锁与实机验收。
